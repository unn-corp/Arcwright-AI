# Project context quick rules

Use when task-relevant context is missing or durable facts need updating.

- Reuse supplied instructions and known facts; refresh only changed context.
- Resolve the active project and nearest relevant config, package, and task files.
  Project skill/config copies precede global fallbacks; host instruction priority
  still applies. Read one effective skill entrypoint, not both copies.
- Discovery is read-only. Do not create folders, edit ignore files, rewrite memory,
  scan unrelated personal files, or call a tracker merely to gather context.
- Read only applicable instructions and the current task's relevant artifacts.
  Inspect names before contents; avoid full catalogs and recursive document dumps.
- Look up factual answers directly. Ask only for a material unresolved user
  decision; preserve existing authorization and decisions.
- Pass concise constraints, verified commands, source paths, and unknowns onward.
  Link accessible artifacts instead of repeating them in every handoff.
- Persist durable facts only within the task's authorized memory scope. Update
  owned generated sections in place, preserving hand-authored instructions.
- Use Unnamed Development MCP only when explicitly requested. Task state stays
  in its chosen local artifacts or tracker; do not relocate it automatically.
- Save temporary evidence through the host, otherwise under the active project's
  `_arcwright/_memory/skill-runs/project-context-<run-id>/`. Installed skills remain
  read-only during execution.

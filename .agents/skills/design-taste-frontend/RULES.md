# Taste frontend rules

- Use for public pages, landing pages, portfolios, and marketing sites.
- Read and preserve the existing `DESIGN.md`; draw a new direction only when appropriate to the request.
- No eyebrows above headings, no em dashes in user-facing copy, and no AI attribution in deliverables. Retain source licenses and required media credits.
- Keep the installed bundle read-only. Use the active project's `_arcwright/_memory/skill-runs/taste-<run>/` for working files and helper output.
- Prefer native Arcwright Code/T3 Code preview tools; use the browser procedure for fallbacks and evidence.
- Choose subject-specific content, honest imagery, readable typography, semantic controls, and reduced-motion support.
- Inspect desktop, tablet, and phone layouts; fix substantive findings through at most three visual critique rounds.
- Do not enlarge scope, invent proof, publish, or add dependencies merely to satisfy a design heuristic.

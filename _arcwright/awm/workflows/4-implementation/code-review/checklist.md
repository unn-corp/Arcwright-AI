# Scoped code review

- [ ] Requested target, relevant requirements/story, and actual base/head/range
  are resolved; committed and applicable local changes are included.
- [ ] Task ownership is distinguished from unrelated workspace edits; no
  universal directory exclusion hides requested product sources.
- [ ] Relevant project standards/context are reused or loaded selectively.
- [ ] Acceptance criteria/completion claims are checked against implementation,
  integration, and appropriate verification evidence.
- [ ] Correctness, failure paths, authorization/data handling, material
  performance risks, and test quality are assessed where relevant.
- [ ] Findings include location, evidence, impact, and severity; duplicates,
  unsupported claims, automatic ledger severity, and issue quotas are absent.
- [ ] Required checks and review limits are stated accurately; optional research
  or broader tests are performed only when they resolve a concrete uncertainty.
- [ ] Fixes and story/sprint updates occur only within existing authorization;
  audit-only requests remain read-only.
- [ ] Authorized tracking uses neutral Review Follow-ups / [Review][Severity]
  labels and source references, without model fields or attribution footers.
- [ ] Final verdict, fixed/open issues, observed checks, and required remaining
  work match the current source; no next-story or external action is implied.
